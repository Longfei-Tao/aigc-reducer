# 运行设置：关闭搜索，开启推理

核验日期：2026-11-01。以下说明设置边界，不表示本项目已在各客户端完成连接或实测。模型、客户端和接入渠道分别决定能力；第三方中转可能不透传参数。

## 三层分别负责什么

| 层次 | 本项目的处理 | 能保证什么 |
|---|---|---|
| 技能与批次请求 | 要求不检索、保留事实、内部复核 | 约束任务行为，不能控制客户端开关 |
| 编辑器 / Agent 宿主 | 使用者关闭搜索工具，选择支持推理的模型和模式 | 以当前会话的实际设置和工具权限为准 |
| API 调用方 | 发送供应商支持的推理参数，移除检索工具及自动检索逻辑 | 需检查最终请求、路由及运行记录，不能只看提示词 |

安装 skill 不会自动关闭搜索或开启深度思考。`SKILL.md` 没有能跨客户端通用控制这两个开关的字段；添加自定义的 `thinking: true` 也不能使宿主自动执行它。

“不检索”表示不获取外部信息；调用云端模型仍需要网络，不等于论文完全在本机处理。保留模型连接、用户文件读取、Python、本地 PDF/OCR 和新 Word 写入权限。依赖安装可在正式处理论文前完成。

## DeepSeek 网页或 App

1. 发送原文前，在当前对话关闭“联网搜索 / 搜索”。
2. 开启当前版本提供的“深度思考 / 思考 / 推理”模式，名称和可用性以界面为准。
3. 新建对话或切换模型后重新检查，不假定上次状态被保留。
4. 粘贴 `batch --prompt` 生成的完整请求，只把最终正文保存为回复文件，不复制思考内容或界面状态文字。

产品没有开关时，不能靠正文中写“开启深度思考”替代。维护者推荐 DeepSeek 的“不检索 + 深度思考”组合，但尚无同批材料的跨模式对照数据，不能承诺更快或降分更大。

## 编辑器与本地 Agent

在 WorkBuddy、Cursor、Claude Code、Copilot、Gemini CLI、OpenCode 等宿主中，先在当前会话或任务的工具权限中关闭 Web Search、浏览网页、联网知识库和搜索类 MCP，包括自动检索与缓存搜索；再在模型选择器中选用支持推理的模型，开启宿主实际支持的思考模式或推理强度。按模型建议设置，不把 DeepSeek 参数照搬到其他供应商。

只写“不搜索”属于行为约束，宿主禁用相关工具才提供权限层面的控制。宿主不能单独禁用检索时，采用本任务“不调用检索工具”的约束，并如实标为开关未确认。用户要求强制保证时，使用能限制工具的宿主或独立调用程序。

### Codex 示例

以下是官方字段示意，**不是覆盖整个配置文件的指令**；只在选定模型支持该推理强度时使用：

```toml
web_search = "disabled"
model_reasoning_effort = "high"
```

`web_search` 控制内建搜索，不自动禁止其他 MCP、连接器或 shell 网络访问；搜索类入口仍需在宿主中限制。`cached` 仍是检索，不能代替 `disabled`。推理字段是否生效取决于模型、客户端和接入渠道。

CC Switch 用户在 CC Switch 中维护并分发，不直接修改生成的 `~/.codex/config.toml` 或共享技能副本。持久化配置修改前先备份、检查冲突并明确影响范围；优先使用宿主支持的当前会话设置。本技能不自动修改这些配置，也不切换账号或供应商。

## API 接入方

本仓库 Python 脚本只处理文档，不调用模型、不读取 API Key。以下是未来集成要求，不是已经实现的模型连接器。

DeepSeek 官方 Chat Completions 参数片段（选用当前支持这些字段的模型）：

```json
{
  "thinking": {"type": "enabled"},
  "reasoning_effort": "high"
}
```

通过 OpenAI Python SDK 调用 DeepSeek 时，`thinking` 放入 `extra_body`；`reasoning_effort` 按接口要求传入。其他供应商逐一按官方接口适配，不能假定所有兼容接口都支持这些字段。

不提供搜索 / 浏览工具，并关闭调用程序的自动检索、RAG 及服务端搜索；仅省略客户端 `tools` 不足以证明第三方宿主没有额外检索。独立的纯文本改写调用可不提供任何工具，文档 Agent 仍保留必要的本地工具。检查最终请求的推理参数、网关透传和运行记录。只保存非敏感设置摘要，不记录密钥、认证头或真实论文。

## 验证与后续优化

区分“已写入设置”“宿主显示已生效”“实际请求与运行记录已核验”。模型自述、回答耗时或思考文字不能独立证明参数生效；状态不可见就标记“无法确认”。

先用合成文档跑一批：确认不调用检索工具、段落数量与顺序一致、数字及引用保留、只返回正文，再执行 check/write 并打开新 Word。行为约束可通过用例检查；平台开关、参数透传及模型连接须在目标宿主另行实测。

后续以同一批脱敏或合成文本，对同一模型比较“搜索关/开 × 推理关/开”四种组合；固定风格指令、批次、模型版本与检测平台，重复运行。分别记录耗时、人工修订量、事实及术语错误、对齐成功率；有真实前后检测报告才记录分数，不把标点变化当成效果证据。跨模型分别评估，不混成一个“最佳设置”。开发评测记录不随用户论文默认交付。

需要更强约束时，再为目标宿主开发适配器，负责能力探测、每次请求设置推理、工具白名单、失败时明确停止及脱敏运行记录。先从一个宿主落地；通用 skill 无法替所有编辑器执行这些控制。
